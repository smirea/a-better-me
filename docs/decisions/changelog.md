# Changelog

- **One file per entry.** Each entry is `changelog/<YYYY-MM-DD>-<slug>.json`, named after the day its PR was written, holding `title` (one line, up to 90 characters), an optional `description` (one line, up to 240), and `tasks`, the ProcrastiMate task ids it addresses. About five PRs merge an hour in parallel, so a shared file would conflict on nearly every merge; separate files never do. `bun scripts/changelog.ts add` writes one and validates it, and every reader (`check`, `bundle`) rejects a malformed file with its path.
- **Every PR that ships code adds one.** The rule and its exemptions are in [Workflow](workflow.md). The check compares the PR with its base and needs a newly added entry, so editing an old one doesn't count.
- **An entry's build is the first TestFlight build that held it, read from git.** A PR can't know its build number: TestFlight builds are archived on master pushes, debounced, and numbered by archive time (`year.MMdd.HHmmss`, `app-ios/scripts/archive`). So after each upload the TestFlight workflow tags the archived commit `testflight/<build number>`. At build time, `bun scripts/changelog.ts bundle` walks HEAD's first-parent history: the commit that added an entry's file is its PR's merge on master, and the first tag at or after it names the build. Entries no tag holds yet ship in the build being made. Tags are written once by CI and never by a PR, so nothing commits back to master and parallel PRs never race on a version field. Entries backfilled from before the tags existed (PRs #153 to #193) carry an explicit `build`, worked out from the TestFlight runs' logs; `build` is for that only.
- **The app bundles the list at build time.** The App target's Bundle Changelog build phase (`app-ios/scripts/bundle-changelog`) runs the generator into `Changelog.json` inside the app, so the screen works offline and needs no server. A TestFlight archive (Release for a device) stamps its own build number and fails on a shallow clone, since it would misattribute every entry; the TestFlight workflow checks out with full history. Every other build, local or CI, says `dev` for untagged entries.
- **More > General > Changelog.** One section per day, newest first, titled Today, Yesterday, or the date. Each row leads with its build in a fixed-width column, then the title and description, and ends with a button that opens the task in ProcrastiMate (`https://procrastimate.stf.lol/inbox?task=<id>`); a menu when the entry has several tasks, nothing when it has none. The navigation subtitle shows the running build. The file is decoded and grouped off the main thread when the screen opens.

# Changelog

- **One file per entry.** Each entry is `changelog/<YYYY-MM-DD>-<slug>.json`, named after the day its PR was written, holding `title` (one line, up to 90 characters), an optional `description` (one line, up to 240), and `tasks`, the ProcrastiMate tasks it addresses. About five PRs merge an hour in parallel, so a shared file would conflict on nearly every merge; separate files never do. `bun scripts/changelog.ts add` writes one and validates it, and every reader (`check`, `bundle`) rejects a malformed file with its path.
- **A task carries its title.** Each task is `{"id", "title"}`, the title copied when the entry is written, because neither the app nor CI can reach ProcrastiMate to look it up. `add --task` takes the `[<title>](<link>)` line every brief lists under its tasks and stores both; a bare id or link still works and stores the id alone, which the app labels "ProcrastiMate task". Readers accept a bare id string too, so entries from PRs written before titles existed keep passing. The entries from before this were backfilled with each task's title as it read on 2026-11-13. A renamed task keeps its old title here; the link still opens the current one.
- **Every PR that ships code adds one.** The rule and its exemptions are in [Workflow](workflow.md). The check compares the PR with its base and needs a newly added entry, so editing an old one doesn't count.
- **An entry's build is the first TestFlight build that held it, read from git.** A PR can't know its build number: TestFlight builds are archived on master pushes, debounced, and numbered by archive time (`year.MMdd.HHmmss`, `app-ios/scripts/archive`). So after each upload the TestFlight workflow tags the archived commit `testflight/<build number>`. At build time, `bun scripts/changelog.ts bundle` walks HEAD's first-parent history: the commit that added an entry's file is its PR's merge on master, and the first tag at or after it names the build. Entries no tag holds yet ship in the build being made. Tags are written once by CI and never by a PR, so nothing commits back to master and parallel PRs never race on a version field. Entries backfilled from before the tags existed (PRs #153 to #193) carry an explicit `build`, worked out from the TestFlight runs' logs; `build` is for that only.
- **The app bundles the list at build time.** The App target's Bundle Changelog build phase (`app-ios/scripts/bundle-changelog`) runs the generator into `Changelog.json` inside the app, so the screen works offline and needs no server. A TestFlight archive (Release for a device) stamps its own build number and fails on a shallow clone, since it would misattribute every entry; the TestFlight workflow checks out with full history. Every other build, local or CI, says `dev` for untagged entries.
- **More > General > Changelog.** One section per day, newest first, under a centered title (Today, Yesterday, or the date) with a rule on each side running to the screen edges. Entries draw straight on the page with separators between them and no card, an exception to [Design](design.md)'s card rule the owner asked for, so the list reads as a feed. Each entry leads with a small line: the whole build number on the left, since it is the name TestFlight and the subtitle use, and the time it was archived on the right in local time, with the date too when that local day differs from the entry's (the number's own digits are UTC). The title then spans the full width, then the description, then one line per task, linking to ProcrastiMate (`Changelog.taskURL`, the web inbox `https://procrastimate.stf.lol/inbox?task=<id>`; it moves to the ProcrastiMate iOS app once that app takes links), its text the task's title cut to one line with an ellipsis, and nothing when there are none. The links first read "Task", or "Task 1", "Task 2" side by side; the owner asked for the titles, one per line. An earlier layout put the build in a narrow left column, wrapped after its day so titles lined up; it went because it squeezed the titles. The navigation subtitle shows the running build. The file is decoded and grouped off the main thread when the screen opens.

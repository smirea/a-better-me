# iOS

- **iPhone only for now.** The app targets iOS 18 on iPhone (`TARGETED_DEVICE_FAMILY = 1`). The scaffold's macOS and iPad support is dropped, because the owner uses the app on an iPhone and keeping macOS compiling would constrain the UI code for no benefit. `swift build` on macOS therefore no longer checks the app. A simulator build through `xcodebuild` or `./scripts/run` is the check.
- **Local-first with SwiftData.** All owner data lives on the device in SwiftData. There is no server sync yet. Models are plain enough to serialize to JSON, because programmatic access through the server is the end goal (see [Product goals](product.md)). While no real data exists, schema changes may wipe the store instead of migrating.
- **Look like MacroFactor Workouts.** Dark theme, the reference app's colors, and its bundled fonts (DM Sans for text, MacroSans for display headings), copied into `Sources/App/Resources/Fonts/`. Shared tokens and components live in `Sources/App/DesignSystem/`. Feature code uses those tokens instead of literal colors and font sizes.
- **Code layout.** `Sources/App/` holds the app. Each product area gets a folder (`Workouts/` for now) with one subfolder per feature. The Xcode project uses a synchronized folder, so new files and resources join the target without editing `project.pbxproj`.
- **Bundled data.** Large read-only data, such as the exercise catalog and its images, ships in the app bundle under `Sources/App/Resources/`. It is generated by scripts and never edited by hand.
- **Verification.** A change is done when it builds for the simulator and the agent has driven the changed screen in the simulator and looked at a screenshot. Pure logic, such as Levels math and progression, lives in plain functions apart from views, so it can get tests once a test target earns its place.

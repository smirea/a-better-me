# Product goals

- **A one-stop tracker for the owner's own habits.** A Better Me is a personal app for one user. It will never ship publicly, so it takes aggressive tradeoffs: no onboarding, no accounts or paywalls, no localization, no accessibility or device-matrix polish beyond what the owner uses, and data migrations may be destructive while the app is young.
- **Re-create MacroFactor and MacroFactor Workouts, then go beyond them.** The owner pays for both apps and likes how they look and work, but neither offers programmatic access. A Better Me rebuilds them so the owner owns the data, then adds features on top. Programmatic access to the owner's own data is the reason the project exists, so every domain model is designed to be exported and synced, not locked inside the client.
- **Copy the reference app by default.** Unless a decision file says otherwise, a feature looks and behaves like the matching screen in MacroFactor (`/Applications/MacroFactor.app`) or MacroFactor Workouts (`/Applications/Runner.app`, process `Runner`). Both run on this Mac and may be driven freely, including changing their settings and data. Cut anything that only makes sense for a commercial multi-user product: subscriptions, social, referrals, coaching upsells, multi-language support.
- **Offline first.** Every feature works without a connection and syncs once one exists, except features that need the network to function. See [Sync](sync.md).
- **Pareto over completeness.** When copying something costs far more than it is worth (for example assets the reference app guards server-side), drop it and record why in the area's decision file.
- **Current focus: Workouts on iOS.** The iPhone app comes first. The web client and the nutrition (MacroFactor) half wait. The first milestone covers the exercise catalog, creating workouts, tracking workouts live, and Levels. See [Workouts](workouts.md).

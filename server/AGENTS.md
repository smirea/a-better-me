# API server

- Routes live in one fetch handler, `src/api.ts`, free of Bun and Node APIs. `src/index.ts` serves it with Bun (`bun run start:server` from the root, or `bun run start` here) over `.data/<checkout>.sqlite`, and `src/worker.ts` on Cloudflare, where the `Space` Durable Object holds the data.
- Settings go through `parseConfig` in `src/config.ts`: `index.ts` passes the generated `src/env.ts`, the Worker its bindings. Add a secret production needs to `REQUIRED_IN_PRODUCTION` there so the server fails at startup without it, and `scripts/secrets.ts` pushes and verifies it on the Worker.
- Sentry: `handle` reports through the `report` it is given, the Sentry SDK module of each runtime. A refused write is a warning, a 5xx or a thrown error an error ([decisions](../docs/decisions/observability.md)).
- The schema is `../shared/db/schema.ts`. A new column needs a default or must be nullable, because both sides add it to existing tables. After changing it, run `bun run generate` from the root and commit `app-ios/Sources/Core/Sync/Generated/SyncSchema.swift`; `scripts/check-generated.ts` fails when it is stale. Declare server-only secrets in the server scope of the root `.env`; edit values only in root `.env.local` and run `env-manager gen --local`.
- `src/agent/` is the agent API ([decisions](../docs/decisions/agent-api.md)): `routes.ts` joins the domain files' route lists (`exercises.ts`, `workouts.ts`, `programs.ts`, `muscles.ts`, `gyms.ts`, `settings.ts`, `body.ts`, `nutrition.ts`, `insights.ts`, `../food/routes.ts`) into the one registry the router and the OpenAPI document both read, so a new operation is one `route({...})` entry in its domain's file with its Zod schemas in `models.ts`. List helpers (`pagedList`, `dayRange`, `fresh`) live in `route.ts`. `src/testing.ts` builds the whole API over an in-memory space for tests. Each `src/agent/<area>.test.ts` drives it like an agent and reads back what a phone would sync, through the `call`, `ok`, and `phone` helpers `testServer` returns. `muscle-model.ts` is the muscle load and recovery formula; `GET /muscle-effects` serves its source verbatim through `muscle-model.source.ts`, which `bun run generate` writes, so it imports nothing. `engine.ts` and `metrics.ts` port the app's derived numbers (trend weight, expenditure, workout stats) and `insights.ts` serves them; change them together with their Swift originals, and keep `src/agent/engine.test.ts` and `src/agent/maintenance.test.ts` on the iOS tests' literals.
- `src/api.test.ts` drives `handle` over an in-memory space from `sync-engine/core`. Add a test only for a rule the tests skill (`~/code/ai-files/skills/tests/SKILL.md`) admits, such as sync, permissions, or a wire format; a route's wiring gets none.
- `src/index.ts` also serves `../app-ios/Assets/` at `/assets/manifests/<version>.json` and `/assets/blobs/<sha256>`, the asset bucket's layout, for Debug iOS builds (`src/assets.ts`). It has no auth and recomputes the manifest per request. The Worker never serves assets.
- `src/images.ts` serves picture bytes at `/api/images` from the host's bucket: the `IMAGES` R2 binding on the Worker, `local-bucket.ts`'s folder under Bun and in tests. Bytes never go in a synced table ([decisions](../docs/decisions/images.md)). Try a change to it under `bun scripts/wrangler-dev.ts` too, since the folder only imitates R2.
- Every route needs a token except `GET /api`, which only explains how to get one (see `docs/decisions/agent-api.md`). Shared contracts belong in `../shared/`; keep them independent of server configuration.
